# Maintain this Astro distribution

Read the root AGENTS.md and .agents/README.md, then memory/project.md,
memory/engineering-contract.md and the decisions relevant to the task.
Read memory/modular-installer-plan.md before changing feature selection,
memory/frontend-conventions.md before UI work and memory/update-plan.md before
proposing an updater. Current human instructions take precedence.

## Find the source of truth

- The root src/ tree is the maintained Astro starter and full feature catalog.
- packages/cli/lib owns create/add, static source inspection, providers, feature
  composition, locale scaffolding, conflicts and rollback.
- packages/cli/template is generated by scripts/prepare-package.mjs. Edit original
  source and allowlists, then run `bun run kit:prepare`; do not patch the template.
- scripts/agent-context is the portable memory seed. Maintainer .agents history
  must not leak into a generated site. Only declared skills are copied.
- website/ owns a separate private toolchain and distribution website. Read its
  AGENTS.md and REFERENCE.md before changing it. Keep it outside consumer output.

Use the installed codebase-memory skill for structural queries and check evidence
coverage. Fall back to exact source reads for missing, stale or unsupported
ranges; a clean coverage result is not proof of an exhaustive audit.

## Preserve the modular installer contract

Creation and later addition use the same feature payloads. Omitted options leave
out unrelated source, domains, dependencies, environment keys and imports. Normal
interactive defaults may include the Welcome demo; --minimal stays minimal.
A later addition must preserve existing custom pages/layouts and report conflicts
before writes rather than silently ignore an occupied registration.

Forms always includes Formatter, Fields is a separate template choice, and Mail
includes its contact Action example. Actions and Content include basic examples.
Content chooses local/API/Strapi/Shopify/other separately from build/live timing.
Remote sources start inactive until configured; installation does not contact a
provider. Keep inactive Action registration in index.ts.example where required.

Locale additions inspect the current static dictionary structure without
executing modules. Preserve custom keys, create empty values and keep unfinished
locales inactive. Never seed new release text over the user's dictionaries or
clone CMS records/translated slugs.

The CLI runs with Node through npx. Consumers choose npm/pnpm/Bun installation
and Node/Bun execution independently; test all six combinations. Explicit missing
tools fail instead of silently changing the choice. Unattended creation follows
the recognized launcher, otherwise npm when available. Our pnpm/Bun maintainer
policy is not a consumer requirement. Public command examples offer matching tabs.
Follow the generated project’s current tool configuration on later additions. Preserve Cloudflare's
Node execution requirement even when Bun launches the script.

Use AST-aware configuration edits and test comments, occupied keys, custom
exports and no-write conflicts. Preserve original input on an application failure;
package-manager side effects have a separate failure boundary.

## Edit docs as a user journey

Display name: Astro. Package identity: @samline/astro. Do not invent a separate
framework brand or imply Astro affiliation. Explain what our distribution adds;
link official Astro docs for framework and adapter behavior.

Keep READMEs and developer docs in English. Give each title and description a
specific purpose. Examples state where to run the command, required features,
actual output and the next step. Do not present a file tree as an executable
snippet or use hidden optional dictionary dependencies. Source-backed references
come from their owning README; website catalogs own public UI copy.

Preserve the approved website presentation and curated Drawer/Ticker/Forms
section. Update the design reference only for a bounded, reviewed design change;
do not refresh hashes merely to silence a failed check.

## Package and release carefully

Install with pnpm; run scripts with Bun. Root and CLI versions stay aligned with
the supported Astro major, with independent minor/patch versions. kit:version
changes release metadata; it does not update generated source or dependencies.
Read the update investigation before adding any update command. The current
metadata has no pristine source hashes for automatic three-way merges.

Maintain allowlists and .npmignore/.gitignore together. Retain .env.example,
portable .agents, component READMEs and required license notices; exclude real
secrets, website, maintainer history, dependencies and outputs. Review upstream
skill licenses before shipping them. Original MIT terms do not replace upstream
licenses; the noncommercial Bun skill is intentionally excluded.

Use focused tests for the behavior changed, then the required root verification
and actual local tarball checks. Changes to website code/configuration require
its verification as well. Useful commands are `bun run verify`, `bun run kit:pack`
and `bun run site:verify`. Check archive contents and generation from the actual
archive, including selected skills and excluded maintainer-only content.

Record evidence, decisions and remaining limits in persistent memory. Distinguish
localhost/build/mock checks from deployment, real service and performance
measurements. Creating a package archive does not publish it. Publication,
deployment, commit or push follow the current user's authorized scope.
