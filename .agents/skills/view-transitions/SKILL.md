# Use view transitions

Read the project's AGENTS.md and .agents/README.md first. ClientRouter is not part
of the generated starter: add it only when the project benefits from continuity
between pages, and tell the owner that every page change becomes a client navigation.
Astro's [view transitions guide](https://docs.astro.build/en/guides/view-transitions/)
owns framework behavior; this skill owns the lessons and the effect vocabulary.
Pick effects from [the effect dictionary](./references/effects.md).

## Add it

1. Import `ClientRouter` from `astro:transitions` once in the layout head every page uses.
2. Audit every script that keeps state in the page. A module script runs once while
   its DOM is replaced, so each one needs an idempotent `setup` on `astro:page-load`
   and a `cleanup` on `astro:before-swap` that removes listeners, timers and observers.
   Fields, Captcha, the theme script, consent and PageLoader already do this.
3. Links that must load natively take `data-astro-reload`. A click handled by your own
   script must call `preventDefault()` first; ClientRouter ignores default-prevented clicks.
4. Expose the route name on `<main>` (for example `data-page-route`) when effects
   depend on the destination.

## Design the vocabulary

One default effect for every page change, one or two exceptions with a reason, and
about 450 ms for ordinary links. Per-route effects read as a demo, not an identity.
Name the header and footer only while navigating
(`:root[data-astro-transition] .site-header { view-transition-name: site-header }`)
and disable their animation so they stay still. Select the destination with
`:root:has(main[data-page-route='...'])` and override exceptions with a flag attribute
such as `:root[data-vt-step]:has(main)` so specificity stays above the defaults. Always
disable pseudo-element animation under `prefers-reduced-motion: reduce`.

## Mistakes to avoid

- **Widgets bound to `<body>`.** ClientRouter replaces the body. A third-party SDK that
  observes the body it started in (HubSpot's v4 forms, for example) never sees the new
  one. Reset its globals and load it again after the body changes, or load such pages
  natively. Forms inside a Drawer `<template>` cannot be found by querying the new document.
- **Styles lost in development only.** Vite injects CSS imported by scripts as
  `<style data-vite-dev-id>` in the head; the head swap removes them and tickers or
  drawers stop. Copy those tags into the incoming head in `astro:before-swap`, development
  only. Production is unaffected, so test both.
- **Duplicate `view-transition-name`.** Two elements with one name in a state cancel the
  whole transition. Name dynamically, only the elements involved, and clear every dynamic
  name at the start of each navigation. A permanent name on a layout element also makes
  it the containing block of its fixed descendants.
- **Viewport units.** `1vmax` is 1% of the larger side: `2.6vmax` is about 33 px, not
  3000 px. Percentage mask positions are relative to free space; use px or viewport units.
- **Scroll order.** Astro resets scroll before `astro:after-swap` and the new snapshot is
  taken afterwards. Adjust scroll in that event so the page does not jump after the transition.
- **Async work in the swap.** The swap is synchronous. Prepare data and decode incoming
  images in `astro:before-preparation` by wrapping `event.loader`. Content restored
  asynchronously after the swap cannot be a morph target; it fades instead.
- **Click origins from a fixed header.** A header click has no useful vertical position;
  place origin effects below the header or at a spot chosen at build time.

## Shared elements and reordering

Name the clicked element and the destination element with the same
`view-transition-name`; give many cards a unique name each plus one
`view-transition-class` to let the browser move them when a filter changes the same page.
The dictionary reference has the full snippets.

## Verify

Do not judge effects in a throttled or hidden preview: frames do not advance. Use a
headless browser, start the navigation and scrub
`document.getAnimations()` filtered to `::view-transition-*` pseudo-elements by pausing
them at fixed `currentTime` values before taking screenshots. Compare every page loaded
directly with the same page reached by navigation (tickers, carousels, drawers, forms,
consent, reveals) and test the production build as well as development.

## Reverting

Record the change in the project's decisions memory with the files touched so it can be
reverted: remove `<ClientRouter />`, the transition component and its markers, and restore
native navigation calls. Components that already follow the lifecycle contract keep
working with full page loads.
